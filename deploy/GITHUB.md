# Разработка на GitHub и автодеплой на VPS

Схема работы: пишете код у себя → пушите ветку → открываете Pull Request → мержите его в `main`
→ GitHub сам проверяет код, заливает его на VPS и перезапускает бота. Если бот не поднялся,
деплой откатывается на предыдущую версию автоматически.

---

## Часть 1. Создать репозиторий

1. [github.com/new](https://github.com/new) → имя `prashna-bot` → **Private** (обязательно
   приватный: в истории могут оказаться чувствительные вещи) → **Create repository**
2. У себя на компьютере, в папке с проектом:

```bash
git init
git add .
git commit -m "Прашна-бот: первая версия"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/prashna-bot.git
git push -u origin main
```

Проверьте, что `.env` **не** попал в репозиторий — он в `.gitignore`, но убедитесь:

```bash
git ls-files | grep -c '\.env$'      # должно вывести 0
```

Если `.env` всё же закоммитился — удалите его из индекса (`git rm --cached .env`), сделайте
новый коммит и **обязательно перевыпустите все ключи**: то, что попало в историю git, считается
утёкшим.

---

## Часть 2. Подготовить сервер

На VPS, от root:

```bash
bash /opt/prashna-bot/deploy/setup-cd.sh
```

Скрипт создаёт пользователя `deployer`, под которым будет ходить GitHub, выдаёт ему право
запускать через sudo ровно один скрипт (`apply.sh`) и ничего больше, генерирует SSH-ключ
и печатает его в конце.

**Скопируйте приватный ключ целиком**, вместе со строками
`-----BEGIN OPENSSH PRIVATE KEY-----` и `-----END OPENSSH PRIVATE KEY-----`.

---

## Часть 3. Прописать секреты в GitHub

Репозиторий → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**.
Добавьте четыре:

| Имя | Значение |
|---|---|
| `SSH_PRIVATE_KEY` | приватный ключ из части 2, целиком |
| `SSH_HOST` | IP вашего VPS |
| `SSH_USER` | `deployer` |
| `SSH_PORT` | `22` (или свой, если меняли) |

---

## Часть 4. Проверить

Репозиторий → вкладка **Actions** → workflow **Deploy to VPS** → **Run workflow**.

Пройдут два этапа: `Проверка кода` (синтаксис, установка зависимостей, тестовый расчёт карты)
и `Деплой на VPS` (заливка файлов, перезапуск, проверка что сервис жив).

Зелёные галочки — всё работает. Дальше деплой запускается сам при каждом мерже в `main`.

---

## Как теперь вести разработку

```bash
git checkout -b feature/новая-фича
# правите код
git add . && git commit -m "Что сделано"
git push -u origin feature/новая-фича
```

GitHub предложит открыть Pull Request. При открытии PR запускается только проверка кода —
на сервер ничего не попадает. Мержите PR → запускается деплой.

Хотите страховку от случайного пуша прямо в `main`: Settings → Branches → Add rule →
Branch name pattern `main` → **Require a pull request before merging**.

---

## Что происходит при деплое

1. `rsync` заливает код в `/opt/prashna-bot/incoming/` (файл `.env` и папка `data` исключены —
   настройки и база живут только на сервере и деплоем не затрагиваются)
2. `apply.sh` от root: делает копию текущего кода в `backups/`, подменяет файлы,
   доставляет зависимости, перезапускает сервис
3. Ждёт 4 секунды и проверяет `systemctl is-active`
4. Если сервис не поднялся — возвращает предыдущую версию, печатает последние 30 строк логов
   и помечает деплой упавшим

Копии кода хранятся 30 дней, потом удаляются.

---

## Если деплой упал

Смотрите вывод шага в интерфейсе Actions — там будут логи сервиса. На самом сервере:

```bash
journalctl -u prashna-bot -n 50
ls -la /opt/prashna-bot/backups/         # список копий
```

Откатиться вручную на конкретную копию:

```bash
systemctl stop prashna-bot
rm -rf /opt/prashna-bot/app
cp -r /opt/prashna-bot/backups/code-2026-09-16-1430/app /opt/prashna-bot/app
chown -R prashna:prashna /opt/prashna-bot
systemctl start prashna-bot
```

## Безопасность

- Пользователь `deployer` не имеет прав root: через sudo ему разрешён ровно один скрипт
  по фиксированному пути. Подменить сам скрипт он тоже не может — файл принадлежит root
- `.env` с ключами никогда не покидает сервер и не попадает в репозиторий
- Ключ SSH используется только GitHub Actions и легко отзывается: удалите строку
  из `/home/deployer/.ssh/authorized_keys`
- Для приватного репозитория GitHub Actions бесплатен в пределах 2000 минут в месяц;
  один деплой занимает около двух минут
