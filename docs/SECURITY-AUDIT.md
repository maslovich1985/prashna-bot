## Что проверялось

`SSH_PRIVATE_KEY`, адрес прокси с логином и паролем.

```bash
gitleaks git --redact --no-banner --log-opts="--all" .
```

`20 commits scanned … no leaks found`.

merge-коммиты, а их gitleaks пропускает, потому что их диффы уже просканированы в ветках.
`--log-opts="--all"` добавляет к текущей ветке все остальные refs, включая ещё не слитые
`origin/feature/admin-unlim` и `origin/feature/prashna-bot`.

## Почему утечек нет

Секреты живут только на VPS: `.env` и `data/` исключены из rsync и с самого первого коммита
перечислены в `.gitignore`. Деплой-ключ и токены лежат в GitHub Secrets, в воркфлоу они
подставляются через `${{ secrets.* }}` и в код не попадают.

## Что защищает дальше

- **Push Protection** — блокирует пуш с распознанным секретом до попадания в историю;
- **Secret Scanning** — сканирует историю и новые коммиты, алертов: 0;
- job `secrets` в `deploy.yml` — gitleaks на каждом PR и перед каждым деплоем.

Первые две включены после перевода репозитория в public: приватным репозиториям они доступны
только с GitHub Advanced Security.

## Если утечка всё же случится

Порядок действий — сначала ротация, потом чистка истории. Вычищенный из истории, но не
отозванный ключ остаётся скомпрометированным: он мог быть склонирован до чистки.

1. `TELEGRAM_TOKEN` — `/revoke` у @BotFather, затем новый токен в `.env` на сервере.
2. `GROQ_API_KEY` — удалить ключ в консоли Groq, создать новый.
3. `SSH_PRIVATE_KEY` — удалить публичный ключ из `~/.ssh/authorized_keys` на VPS,
   сгенерировать новую пару, обновить секрет в настройках репозитория.
4. `LLM_PROXY` — сменить пароль у провайдера прокси.
