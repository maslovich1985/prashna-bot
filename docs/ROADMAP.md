# Roadmap: платный сервис, UX, инфраструктура

От прототипа к платному продукту: подписки, пробные вопросы, рефералка.
Порядок этапов — по зависимостям, не по важности.

Здесь — решения и обоснования. Исполняемый бэклог с ID, DoD и зависимостями —
в [TASKS.md](TASKS.md).

## 1. Ограничения

- **VPS 1 vCPU / 1 ГБ** → SQLite, polling, без Docker/Redis, семафоры на CPU, swap обязателен.
- **Groq только через прокси** → единственная точка отказа платного пути.
- **Русский домен**, i18n не планируется.
- **Нет юрлица** → Telegram Stars.

## 2. Уже есть — не переделывать

| Что | Где |
| --- | --- |
| `logging` вместо `print()`, уровень из `LOG_LEVEL` | ротация — systemd journal |
| Бэкап БД: `sqlite3 .backup` + чистка старше 14 дней | `deploy/backup.sh` |
| Автооткат деплоя по `systemctl is-active` | `deploy/apply.sh` |
| CI-гейт: `compileall` + смоук карты | `.github/workflows/deploy.yml`, job `check` |
| Кнопка «Отправить геолокацию» | `app/bot.py:56` |
| Изоляция данных: все запросы по `user_id`, `/stats` под `admin_ids` | `app/db.py`, `app/bot.py:185` |
| Карта уходит до вызова LLM | прашна-путь в `app/bot.py` |
| Ретраи Groq 3× с `retry-after` | `app/llm.py` |
| Троттлинг геокодера ≤1 req/sec | `app/geo.py` |
| Город хранится постоянно, до следующей смены | `users.place/lat/lon/tz`, `upsert_user` в прашна-пути не перетирает его через `COALESCE` |

## 3. Отклонено

| Идея | Почему нет | Вместо |
| --- | --- | --- |
| Alembic + `pg_dump` | Подразумевают Postgres; на 1 ГБ он съест половину памяти при нагрузке в единицы запросов в минуту | `PRAGMA user_version`, §4.5 |
| Taskiq / Celery + Redis | Бот не блокируется: aiogram крутит каждый `Update` отдельно, карта в `to_thread`, Groq — `await`. Реальные риски — 429 и конкуренция за ядро | Семафоры, §10.1–10.2 |
| Docker + compose | Заменяет рабочий rsync+systemd с автооткатом. `FLG_MOSEPH` = файлов эфемерид нет, разница среды только в версии Python | — |
| Вебхуки | Нужны домен, TLS, nginx; задержка polling незаметна | — |

Триггеры для пересмотра — §12.

## 4. Этап 1 — фундамент

### 4.1 Ruff

```toml
[tool.ruff]
line-length = 100
target-version = "py312"

[tool.ruff.lint]
select = ["E", "F", "W", "I", "UP", "B", "ASYNC", "RUF"]

[tool.ruff.lint.per-file-ignores]

```

В job `check`: `ruff check .`, затем `ruff format --check .`.
`format --check` включать после одноразового `ruff format` отдельным коммитом.

### 4.2 pytest

`requirements-dev.txt`: `pytest`, `pytest-asyncio`, `ruff`. Тесты в `tests/` — `app` уезжает
на VPS через rsync целиком.

Первая партия, без сети:

- `detect_house` — 15–20 формулировок по всем 12 домам + фолбэк на дом 1. Самая хрупкая
  эвристика проекта, ломается молча.
- `build_chart` — фиксированные дата и координаты → 9 планет, 8 варг, лагна по эталону.
  Ловит смену аянамши и регресс pyswisseph.
- `judgment_factors` — непустой список, все `str`.
- `db.check_and_bump` — на `tmp_path`: лимит, кулдаун, изоляция по `user_id` и дню.
- `render_short` / `render_chart_text` — ≤4096 символов, маркер `Лагна:`.

Подвох: `app/config.py` читает env на импорте → фикстура ставит `DB_PATH` до первого импорта
`app.config`, либо `monkeypatch.setattr(app.db, "settings", ...)`.

Инлайн-смоук из `deploy.yml` удалить, шаг становится `pytest -q`.

### 4.3 Секреты

Бот-токен теперь и платёжный ключ — с ним выпускают инвойсы от вашего имени.

- GitHub Secret Scanning + Push Protection.
- `gitleaks/gitleaks-action@v2` с `fetch-depth: 0`, иначе проверяется только последний коммит.
- Аудит истории: `TELEGRAM_TOKEN`, `GROQ_API_KEY`, `SSH_PRIVATE_KEY`, адрес прокси с логином.
  Утекало → **ротировать**, не только вычистить историю.
- `.gitignore`: `.env`, `data/`, `backups/`, `*.sqlite3*` — включая `-wal` и `-shm` (WAL).

### 4.4 Бэкапы вне VPS — блокирует приём платежей

Копии `backup.sh` лежат на том же диске. Это не бэкап. Потеря `payments` = возвраты вручную
по перепискам.

- systemd timer `prashna-backup.timer`, ежедневно ~03:30.
- `gzip -9` + выгрузка: `sendDocument` в закрытый канал (`BACKUP_CHAT_ID`, тот же токен,
  ноль зависимостей) либо `rclone` в S3. Лимит бота — 50 МБ на документ.
- Раз в квартал — учебное восстановление.

### 4.5 Миграции

Схема наращивается только обратносовместимо; дальше — пять новых таблиц и колонок.

```python
MIGRATIONS: list[str] = [
    "ALTER TABLE users ADD COLUMN referrer_id INTEGER",   # индекс 0 → user_version 1
]

def migrate() -> None:
    with conn() as c:
        v = c.execute("PRAGMA user_version").fetchone()[0]
        for i, sql in enumerate(MIGRATIONS[v:], start=v):
            c.executescript(sql)
            c.execute(f"PRAGMA user_version = {i + 1}")
```

`init()`: `SCHEMA` (с нуля) → `migrate()` (догон). Вызов из `run()` до polling.
Перед `migrate()` дёргать `backup.sh` — иначе откат кода останется с уехавшей схемой.

### 4.6 Рефакторинг на `Router`

Хэндлеры — замыкания внутри `register(dp)` (`app/bot.py:70`), снаружи не импортируются, то есть
не тестируются. Этапы 2–6 добавят десяток хэндлеров — делать до них.

1. Хэндлеры на уровень модуля, на `Router`; `register(dp)` → `dp.include_router(router)`.
2. Разбить: `handlers/basic.py`, `place.py`, `prashna.py`, `billing.py`, `privacy.py`.
3. Тексты в `app/texts.py` — их станет много (§8).

Тесты через `dp.feed_update(bot, update)` с подменённой сессией. `aiogram-tests` даёт
`MockedBot`, но отстаёт от версий aiogram — при конфликте с `aiogram>=3.31` свой стаб на
~30 строк надёжнее.

Покрыть: `/start`, `/help`, `/city` (+ «город не найден»), `/me`, `/history` на пустой,
`/stats` для не-админа, прашна-путь с мокнутым `llm.interpret` (карта до ответа LLM).

### 4.7 Sentry

`SENTRY_DSN` (пусто = выключено), `SENTRY_ENV`. В `run()` до polling:
`sentry_sdk.init(dsn=..., environment=..., traces_sample_rate=0.0, send_default_pii=False)`.

`send_default_pii=False` обязательно: текст вопроса — данные о здоровье, деньгах, отношениях.
Дефолтной интеграции с `logging` хватает; мидлварь — только для тега `user_id` и имени команды.

## 5. Этап 2 — квоты и пробные вопросы

Работает без оплаты: квота исчерпана → отказ.

### 5.1 Приоритет прав

```
admin (ADMIN_IDS)   → безлимит
активная подписка   → суточный лимит тарифа
пакет / бонусы      → questions_left, без привязки к суткам
пробные             → 2 вопроса пожизненно
иначе               → отказ + экран тарифов
```

Пробные **пожизненные**, не суточные: иначе подписка не нужна — текущие 5 в день покрывают
любого. `DAILY_LIMIT` становится полем тарифа.

### 5.2 Тарифы — в `app/constants.py`

Меняются кодом через ревью, не в БД.

```python
TRIAL_QUESTIONS = 2
REFERRAL_BONUS  = 2
REFERRAL_MAX    = 10

PLANS: dict[str, Plan] = {
    "month":  Plan(title="Подписка на месяц", days=30,  stars=..., daily_limit=10),
    "year":   Plan(title="Подписка на год",   days=365, stars=..., daily_limit=10),
    "pack10": Plan(title="10 вопросов",       days=0,   stars=..., questions=10),
}
```

Разовый пакет — сразу: конвертирует не готовых на подписку, стоит те же 20 строк.

### 5.3 Схема

```sql
CREATE TABLE IF NOT EXISTS entitlements (
    user_id        INTEGER PRIMARY KEY,
    plan           TEXT,
    expires_at     TEXT,                         -- NULL для пакетов
    questions_left INTEGER NOT NULL DEFAULT 0,   -- пакеты и реферальные бонусы
    trial_used     INTEGER NOT NULL DEFAULT 0,
    updated_at     TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS payments (
    charge_id   TEXT PRIMARY KEY,                -- telegram_payment_charge_id
    user_id     INTEGER NOT NULL,
    plan        TEXT NOT NULL,
    stars       INTEGER NOT NULL,
    paid_at     TEXT NOT NULL,
    refunded_at TEXT
);
```

`charge_id` как PRIMARY KEY = защита от двойной выдачи.
Срок подписки проверять лениво (`expires_at > now`) — планировщик на дешёвом VPS не нужен.

### 5.4 `reserve` / `commit` / `release`

**Вопрос списывается только за доставленное толкование.**

Сейчас: `check_and_bump` → карта → `llm.interpret`. Прокси отвалился — вопрос списан.

Порядок:

1. `reserve(user_id)` — проверка права и списание, возвращает токен.
2. Проверка валидности прашны (§5.5). Отказ → `release`, LLM не вызывается.
3. Карта + отправка пользователю.
4. `llm.interpret`.
5. Успех → `commit(token)`; любой сбой → `release(token)`.

`try/finally` с флагом `committed`, не `except` по списку типов: неучтённое исключение тоже
обязано вернуть квант.

### 5.4.1 Что списывается

| Событие | Списывать | Пользователю |
| --- | --- | --- |
| Прокси недоступен, Groq 5xx | Нет | «Сервис толкования временно недоступен, вопрос не списан» |
| Groq 429 после ретраев | Нет | «Высокая нагрузка, попробуйте через несколько минут» |
| Groq 401/403 — ключ протух, отозван, кончился биллинг | Нет | Общее «недоступен» + **алерт админу**: само не рассосётся |
| Таймаут | Нет | «Ответ не пришёл вовремя» |
| Ответ пустой или короче `MIN_ANSWER_LEN` | Нет | Пустой ответ — не толкование |
| Ответ обрезан по `groq_max_tokens` | **Да** | + «толкование могло быть сокращено» |
| `build_chart` упал | Нет | «Не удалось рассчитать карту» + алерт: это баг, не внешний сбой |
| Геокодер недоступен, нет геоданных | Нет | Проверять **до** `reserve` — место нужно для лагны |
| Невалидная прашна (§5.5) | Нет | Причина + время следующей попытки |
| Telegram не принял толкование | Нет | Сохранить в `prashna`, отдать через `/chart` |
| Рестарт между `reserve` и `commit` | Нет | см. ниже |
| `/cancel` после `reserve` | Нет | — |
| Толкование доставлено, но не понравилось | **Да** | Возврат не даёт другого ответа — в `/terms` |

**Рестарт между `reserve` и `commit`** (деплой, OOM): `reserve` пишет `reserved_at` в `usage`,
`run()` при старте возвращает резервы старше `RESERVE_TTL` (5 мин). Одна функция, один вызов.

**Алерты админу** отдельно от Sentry: 401/403 от Groq и падение `build_chart` → сообщение в
Telegram из `ADMIN_IDS`, дедупликация не чаще 1/30 мин на тип. Протухший ключ = сервис стоит
целиком, знать надо в ту же минуту.

Каждая строка «Нет» — отдельный тест: мок `llm.interpret` с исключением → `remaining()` не изменился.

### 5.5 Невалидная прашна

Есть классические признаки, при которых карта непригодна для суждения. Сейчас бот толкует любую.
Для платного — продажа пустышки.

**Считает код, не LLM** (инвариант `CLAUDE.md`): новый модуль `app/astro/validity.py`,
пороги — в `app/astro/constants.py`.

| Категория | Поведение |
| --- | --- |
| `reject` — непригодна | Квант возвращён, LLM не вызывается, сообщаем причину и **через сколько минут** карта станет годной |
| `caution` — слабая, но читаемая | Списываем, толкование с оговоркой о пониженной надёжности |

### 5.5.1 Кандидаты в `reject`

Порядок реализации = порядок списка, от дешёвого к астрологическому:

1. **Вопрос без ясного дома.** `detect_house` без совпадений молча возвращает дом 1 → сейчас
   выдаётся уверенное толкование по случайному дому. Балл ниже `HOUSE_MIN_SCORE` → отказ,
   просьба переформулировать + примеры из справки (§8.2). Самое частое и дешёвое правило.
2. **Повторный вопрос.** Заявлен в `WELCOME`, но не проверяется. Та же лагна + близкий текст
   за последние N часов → отказ со ссылкой на `/chart <id>`. Закрывает дыру в экономике:
   перебор формулировок ради желаемого ответа.
3. **Лагна в гандānте** — стык водного и огненного знаков (конец Рака / Рыб / Скорпиона).
4. **Лагна в бхава-сандхи** — ~1° от границы знака: при целых знаках (`b"W"`) минуты дуги
   меняют привязку дома.
5. **Луна в гандānта-накшатре** — стыки Ашлеша–Магха, Джьештха–Мула, Ревати–Ашвини.
6. **Кшина-чандра** — Луна в новолунии.

`caution`: Луна в 6/8/12 от лагны, сожжённый или ретроградный хозяин лагны, отсутствие связи
хозяина лагны с хозяином дома вопроса. Скорее всего уже посчитано в `judgment_factors` —
переиспользовать, не дублировать.

### 5.5.2 «Когда попробовать снова»

Отказ без срока бесполезен: пользователь ткнётся снова и решит, что бот сломан.

Лагна проходит знак ~2 часа, гандānта и сандхи — единицы градусов, то есть 5–20 минут.
Перебор шагом по минуте вперёд (максимум ~3 часа) до первого «годно», **по упрощённой функции
(только лагна и Луна)**: 180 вызовов полного `build_chart` с 8 варгами положат 1 vCPU.

Ответ: «Спросите снова после 14:35 — сейчас лагна на стыке знаков».
Для повторного вопроса срока нет — ссылка на прежний ответ. Для «нет ясного дома» —
переформулировка.

### 5.5.3 Прозрачность и абьюз

- Причина человеческим языком, без терминов без расшифровки.
- Карту при отказе всё равно показать — видно, что расчёт был.
- Отказы писать в `prashna` с пометкой причины; доля отказов по каждой причине — в `/stats`.
- **Отказ = бесплатный расчёт карты = CPU.** `COOLDOWN_SECONDS` применять и к отказам,
  число отказов за сутки ограничить `MAX_REJECTS_PER_DAY` в отдельной колонке `usage` —
  иначе цикл «отказ → снова» заменяет исчерпанные платные вопросы.

### 5.5.4 Тесты

- по фиксированному UTC-времени и координатам на каждое включённое правило `reject`;
- нормальная карта → `ok`, ни одного ложного отказа;
- повторный вопрос: та же лагна + похожий текст → `reject`, другой текст → `ok`;
- `detect_house` ниже порога → `reject`;
- «когда снова» возвращает момент в будущем, и в этот момент `validity` даёт `ok`;
- `reject` не списывает квант, `caution` — списывает;
- превышен `MAX_REJECTS_PER_DAY` → отказ без расчёта карты.

## 6. Этап 3 — оплата

### 6.1 Telegram Stars (XTR)

| Вариант | Нужно | Вывод |
| --- | --- | --- |
| **Stars (XTR)** | Только бот-токен | **Берём.** Нет юрлица, договора, `PROVIDER_TOKEN`, вебхука; чеки формирует Telegram. Комиссия ~30%, вывод через Fragment на TON спустя 21 день |
| Payments + ЮKassa | Самозанятость/ИП, договор, чеки | Позже. Абстракцию «провайдер платежей» заранее **не** строить: выдача доступа от способа оплаты не зависит |
| Крипта, ручные переводы | — | Ручная сверка, нет идемпотентности |

`sendInvoice` с `currency="XTR"`, **без** `provider_token`,
`prices=[LabeledPrice(label=..., amount=<звёзды>)]` — без умножения на 100, как в фиате.

### 6.2 Обязательные хэндлеры

- `@dp.pre_checkout_query()` → `answer(ok=True)`. **Ответ за 10 секунд**, иначе Telegram отменит
  платёж. Внутри — только проверка payload по своей БД: ни Groq, ни прокси, ни геокодера.
- `@dp.message(F.successful_payment)` → выдача доступа.
- `/paysupport` — требование Telegram для платёжных ботов.
- `/terms` — что продаётся, что возврат не даёт другого ответа.

### 6.3 Идемпотентность

`successful_payment` приходит повторно при ретраях Telegram и рестарте бота. `INSERT` в
`payments` и продление `entitlements` — в одной транзакции (`db.conn()` коммитит на выходе);
конфликт по `charge_id` → выходим молча.

Продление, не перезапись: `expires_at = max(now, expires_at) + days`, иначе оплата месяца
поверх активной подписки сжигает остаток.

### 6.4 Возвраты

`refundStarPayment(user_id, charge_id)` админской командой: ставит `refunded_at`, отзывает
выданное. Правила — в `/terms` и `/paysupport`.

## 7. Этап 4 — приватность

Делать до появления платежей, иначе `/delete_me` переписывается поверх живой `payments`.

### 7.1 `/privacy`

Что хранится (вопрос, время, место, карта, ответ), зачем, сколько, кому передаётся —
**текст вопроса уходит в Groq через прокси, назвать прямо**, что не продаётся, как удалить.

### 7.2 Две операции

| Команда | Что делает |
| --- | --- |
| `/forget` (есть, `app/bot.py:178`) | Только история прашн. В интерфейсе назвать «Очистить историю» — текущее имя обещает больше |
| `/delete_me` (новое) | `prashna`, `users`, `usage` + обнуление `entitlements` |

`/delete_me` — с подтверждением инлайн-кнопкой: необратимо и сжигает оплаченную подписку.
Сказать об этом в подтверждении, иначе первый кейс в `/paysupport`.

### 7.3 Два подводных камня

**Удаление сбрасывает пробные** → снова 2 бесплатных, бесконечно. Строка в `entitlements` не
удаляется целиком: остаётся надгробие — `user_id`, `trial_used`, `questions_left`, `expires_at`,
остальное обнулено. Личных данных нет (числовой ID без имени, города, вопросов). Написать в
`/privacy`: «сохраняем числовой идентификатор и счётчик пробных, чтобы лимит нельзя было обойти».

**`payments` удалять нельзя** — `refundStarPayment` требует `charge_id`, плюс учёт. Текстов
вопросов там нет. Тоже в `/privacy`.

### 7.4 Видимость чужих данных — утечки нет

## 8. Этап 5 — UX

Сейчас интерфейс — `WELCOME` (`app/bot.py:29`, стена на 20 строк, она же `/help`) плюс восемь

2. **Как задать вопрос** — конкретный, вызревший, «да/нет», одна тема; 3–4 хороших примера и
   столько же плохих рядом. Снижает поток «почему ответ невнятный».

## 9. Этап 6 — рефералка

`https://t.me/<bot>?start=ref<user_id>`; `CommandStart` есть (`app/bot.py:72`), нужен разбор
deep-link аргумента.

```sql
ALTER TABLE users ADD COLUMN referrer_id   INTEGER;
ALTER TABLE users ADD COLUMN referral_paid INTEGER NOT NULL DEFAULT 0;
```

Бонус приглашающему **после первого вопроса** приглашённого, не после `/start`:

- `referrer_id` пишется только если `NULL` и пользователь новый — иначе старый
  «переприглашается» под разными ссылками.
- Самоприглашение отбрасывается.
- Начисление — в той же транзакции, что `commit` первого вопроса, и ставит `referral_paid = 1`.
- `REFERRAL_MAX = 10`: без лимита это ферма мультиаккаунтов, регистрация в Telegram дешевле
  двух вопросов.
- Бонус в `questions_left`, не в `trial_used` — иначе пропадёт при обнулении пробных и смешает
  сущности в отчётах.
- Приглашённому бонус **не** даём: у него и так 2 пробных, иначе «сам себя пригласил вторым
  аккаунтом» выгодно вдвойне.

Уведомление приглашающему («друг задал первый вопрос, +2 вопроса») — именно оно делает механику
рабочей. Имя друга **не** сообщать: он не давал согласия на раскрытие факта обращения к
астрологическому боту.

## 10. Этап 7 — устойчивость

### 10.1 Прокси

- Таймаут прокси **меньше** `GROQ_TIMEOUT=90`: 45–60 с + сообщение «ответ занимает больше
  обычного». Иначе пользователь ждёт полторы минуты в неизвестности.
- `LLM_PROXY_FALLBACK` — второй адрес, перебор по списку. Существующие ретраи бьют в тот же
  адрес и от падения прокси не спасают.
- Раздельные счётчики ошибок прокси и Groq (429 / 5xx / таймаут), в Sentry — тегом.
- Health-пинг при старте: `log.warning`, бота не валить — карта считается и без LLM.

### 10.2 CPU

`build_chart` — блокирующий pyswisseph в `to_thread`. На одном ядре пять расчётов конкурируют,
бот перестаёт отвечать даже на `/start`.

- `asyncio.Semaphore(2)` вокруг `to_thread(build_chart, ...)`.
- Отдельный `LLM_CONCURRENCY` (по умолчанию 3) на Groq — ограничение сетевое, значение другое.
- Замерить `build_chart` на целевом VPS. Кэшировать варги бессмысленно (карта уникальна для
  момента), при заметной задержке — урезать число варг на бесплатном пути.

### 10.3 RAM

- `TimezoneFinderL` вместо полного: для часового пояса города точности хватает,
  `timezonefinder` — основной потребитель памяти.
- Swap 1–2 ГБ: без него OOM-killer убьёт бота в пике, автооткат `apply.sh` этого не заметит.
- В юните: `MemoryMax=`, `Restart=always`, `RestartSec=5`.

## 11. Этап 8 — наблюдаемость

- **`/stats`**: платежи за сутки и месяц, конверсия «пробные исчерпаны → оплата», возвраты,
  реферальные начисления, доля отказов по причинам (§5.5.3), ошибки прокси и Groq, p95 времени
  LLM, попадания геокэша, топ-города. Хранить в таблице `events` — рестарт обнулит память.
- **Структурные логи**: мидлварь кладёт `update_id` и `user_id` в `contextvars`,
  `logging.Filter` подмешивает в каждую запись, формат JSON для `journalctl -o cat | jq`.
  Не трогать до первого инцидента, который сложно разобрать текущими логами.
- **Dependabot** на `pip` и `github-actions`. Нижние границы вместо пинов — осознанное решение,
  так что нужен в основном для Actions и уязвимостей.

## 12. Отложено — по триггеру

| Что | Триггер | Цена |
| --- | --- | --- |
| Docker + compose | Апгрейд VPS **и** второй сервис | Переписать `apply.sh`, потерять автооткат, собирать `pyswisseph` в образе |
| Вебхуки | Заметная задержка polling или несколько инстансов | Домен, TLS, nginx, `secret_token` |
| Postgres + Alembic | Несколько процессов или БД > ~1 ГБ | Переписать все запросы `app/db.py`, +сервис, `pg_dump` |
| Taskiq / Celery + Redis | Рассылки, отчёты, генерация файлов | Воркер отдельным юнитом, Redis, дубль конфига |
| ЮKassa вместо Stars | Оборот перекрывает 30% и отчётность | Самозанятость/ИП, договор, чеки |
| i18n | Нерусская аудитория | — |

Первый ожидаемый триггер — апгрейд VPS, не рост кода.

## 15. Открытые вопросы

1. **Цены в звёздах** для `month`, `year`, `pack10` — с оглядкой на комиссию ~30% и стоимость
   токенов Groq на ответ.
2. **Реальная цена живой консультации** для §8.5 — проверяемая, с 2–3 площадок.
3. **Суточный лимит подписки** (`daily_limit=10` в примере) — упирается в бюджет Groq и §10.2.
4. **Куда выгружать бэкап**: закрытый канал или S3 через `rclone`.
5. **Возврат при `/delete_me` с активной подпиской** — нужна ли ручная политика.
6. **Какие правила валидности включать и с какими порогами** (§5.5.1) — решение астрологическое.
   Нужны: список на старт, `HOUSE_MIN_SCORE`, ширина бхава-сандхи, окно повторного вопроса,
   что в `caution`, что в `reject`. Начать с пунктов 1–2, геометрию добавлять по одному правилу,
   глядя на долю отказов. Бот, отказывающий в половине случаев, воспринимается как сломанный,
   даже если правила верны.
7. **`MAX_REJECTS_PER_DAY`** — компромисс между защитой CPU и раздражением пользователя,
   которому не повезло со временем.
