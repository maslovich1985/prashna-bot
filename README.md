# Прашна-бот — ведическая хорарная астрология в Telegram

Бот строит **прашна-кундали на момент вопроса** (Swiss Ephemeris, сидерический зодиак,
аянамша Лахири, дома «целый знак»), рассчитывает классические факторы суждения и передаёт
их в **Groq** для толкования на русском языке.

Ключевой принцип: **LLM ничего не вычисляет**. Все положения планет, варги, аруда,
вимшоттари-даша и панчанга считаются кодом; Groq получает готовую карту и только
интерпретирует её по правилам прашна-шастры.

---

## 1. Что умеет бот

| Возможность | Детали |
|---|---|
| Расчёт карты | Лагна с точностью до секунды дуги, 9 граха, накшатры и пады, ретроградность, сожжение, достоинства (экзальтация / мулатрикона / свой знак / друг / враг / падение) |
| Дома | Целый знак (whole sign), владыки всех 12 домов и их положение |
| Варги | D1, D2 (хора), D3 (дреккана), D4 (чатуртхамша), D7 (саптамша), D9 (навамша), D10 (дашамша), D12 (двадашамша) |
| Аспекты | Граха дришти со специальными аспектами Марса, Юпитера, Сатурна, Раху/Кету |
| Аруда | Аруда лагна (AL) и аруда дома вопроса |
| Даша | Вимшоттари маха / антар / пратьянтар от Луны момента вопроса |
| Панчанга | Титхи, пакша, накшатра Луны, йога, карана, вара, владыка хоры |
| Дом вопроса | Определяется автоматически по ключевым словам вопроса (1–12 бхава) |
| Толкование | Groq (по умолчанию `llama-3.3-70b-versatile`): вердикт, обоснование, сроки, помехи, совет |
| Место | Геокодирование города (Nominatim) + часовой пояс (timezonefinder) или геолокация Telegram |
| Хранение | SQLite: профиль, история прашн с полной картой, геокэш |
| Антиспам | Дневной лимит и кулдаун между вопросами на пользователя |

Команды бота: `/start`, `/help`, `/city <город>`, `/me`, `/history`, `/chart <id>`, `/forget`,
`/cancel`, `/stats` (для админов из `ADMIN_IDS`).

## 2. Что понадобится

1. **VPS на Beget** — минимальной конфигурации достаточно: 1 vCPU, 1 ГБ RAM, 10 ГБ диска,
   ОС **Ubuntu 22.04/24.04** или Debian 12. Бот работает через long polling, поэтому
   ни домен, ни белый IP, ни SSL, ни nginx не нужны.
2. **Токен Telegram-бота** — от [@BotFather](https://t.me/BotFather): `/newbot` → имя → username →
   вы получите строку вида `123456789:AA...`.
3. **API-ключ Groq** — [console.groq.com](https://console.groq.com) → *API Keys* → *Create API Key*.
   Ключ показывается один раз, сохраните его.
4. **SSH-доступ** к VPS (пароль или ключ) — выдаётся в панели Beget при создании сервера.

> Важно: `pyswisseph` считает по встроенной теории Мошье (`FLG_MOSEPH`) — скачивать файлы
> эфемерид не нужно. Точность положений планет — доли угловой секунды для нашей задачи.

## 3. Развёртывание на Beget VPS — по шагам

### Шаг 1. Создать сервер

Панель Beget → **VPS** → *Создать сервер* → тариф от 1 ГБ RAM → образ **Ubuntu 24.04** →
регион на выбор → создать. В письме/панели появятся IP-адрес и root-пароль.

### Шаг 2. Подключиться по SSH

```bash
ssh root@ВАШ_IP
```

При первом входе смените пароль root и обновите систему:

```bash
passwd
apt update && apt upgrade -y
```

Рекомендуется сразу настроить вход по ключу и отключить парольный вход
(`/etc/ssh/sshd_config`: `PasswordAuthentication no`, затем `systemctl restart ssh`).

### Шаг 3. Загрузить проект на сервер

Вариант А — архивом со своего компьютера:

```bash
# на локальной машине, в папке с распакованным проектом
scp -r prashna-bot root@ВАШ_IP:/root/
```

Вариант Б — через git, если вы положили проект в репозиторий:

```bash
apt install -y git
git clone https://github.com/ваш-аккаунт/prashna-bot.git /root/prashna-bot
```

### Шаг 4. Запустить установщик

```bash
cd /root/prashna-bot
bash deploy/install.sh
```

Скрипт делает всё сам: ставит системные пакеты, создаёт системного пользователя
`prashna`, копирует код в `/opt/prashna-bot`, создаёт venv, ставит зависимости,
кладёт unit-файл в systemd, включает автозапуск и настраивает ufw.

### Шаг 5. Заполнить `.env`

```bash
nano /opt/prashna-bot/.env
```

Минимум, что нужно вписать:

```ini
TELEGRAM_TOKEN=123456789:AA...ваш_токен
GROQ_API_KEY=gsk_...ваш_ключ
ADMIN_IDS=123456789          # ваш Telegram ID (узнать: @userinfobot)
GEOCODER_UA=prashna-bot/1.0 (contact: ваша@почта)
```

Остальные параметры описаны в разделе 5. Сохранить: `Ctrl+O`, `Enter`, `Ctrl+X`.

### Шаг 6. Запустить и проверить

```bash
systemctl start prashna-bot
systemctl status prashna-bot          # должно быть active (running)
journalctl -u prashna-bot -f          # живые логи, Ctrl+C для выхода
```

В логах должна появиться строка `Бот @ваш_бот запущен`.

### Шаг 7. Проверить в Telegram

Откройте своего бота → `/start` → `/city Томск` → напишите вопрос,
например: «Получу ли я оффер на позицию фронтенд-разработчика до конца года?»

Бот ответит двумя сообщениями: сводка карты, затем толкование.

## 4. Ежедневная эксплуатация

```bash
systemctl restart prashna-bot           # перезапуск (после правки .env)
systemctl stop prashna-bot              # остановить
journalctl -u prashna-bot -n 200        # последние 200 строк логов
journalctl -u prashna-bot --since today # логи за сегодня

bash /opt/prashna-bot/deploy/backup.sh  # бэкап базы
bash /opt/prashna-bot/deploy/update.sh /root/prashna-bot   # обновить код
```

Автоматический ежедневный бэкап делает systemd-таймер `prashna-backup.timer` — он ставится
и включается в `install.sh`, cron для этого не нужен. Снимок снимается через
`sqlite3 .backup` (согласованная копия при включённом WAL), проверяется `PRAGMA integrity_check`
и сжимается `gzip -9`; архивы старше 14 дней удаляются.

```bash
systemctl list-timers prashna-backup    # когда следующий запуск и когда был прошлый
systemctl start prashna-backup.service  # снять бэкап немедленно
journalctl -u prashna-backup -n 50      # что было в последних запусках
ls -lh /opt/prashna-bot/backups         # сами архивы
```

### Копия за пределами VPS

Архив на том же диске не спасёт от потери диска, поэтому `backup.sh` отправляет его в Telegram
тем же ботом. Получателем может быть и закрытый канал, и личка владельца — для скрипта разницы
нет.

**Проще всего — личка.** Узнать свой id: написать [@userinfobot](https://t.me/userinfobot),
он ответит `Id: 123456789`. Бот должен получить от вас хотя бы один `/start`, иначе Telegram
вернёт `403: bot can't initiate conversation with a user`.

**Канал** аккуратнее, если бэкапы не должны мешаться в переписке: создать приватный канал,
добавить бота администратором с правом публикации, затем переслать **пост из канала**
`@userinfobot` — он покажет id вида `-100…`. Пересылка обычного сообщения даёт ваш
собственный id, а не канала.

Проверить id, не трогая `.env`:

```bash
TOKEN=$(grep '^TELEGRAM_TOKEN=' /opt/prashna-bot/.env | cut -d= -f2-)
curl -s "https://api.telegram.org/bot$TOKEN/getChat?chat_id=<id>"
```

`"ok":true` — можно дописывать в `/opt/prashna-bot/.env`:

```
BACKUP_CHAT_ID=782739008
```

Отдельный токен не нужен — используется `TELEGRAM_TOKEN` бота.

Если `BACKUP_CHAT_ID` не задан, скрипт отрабатывает штатно и просто оставляет архив на VPS.
Если чат недоступен или Bot API вернул ошибку, скрипт завершается ненулевым кодом — юнит
попадает в `failed`, и это видно в `systemctl list-timers` и `journalctl`. Локальный архив при
этом сохраняется. Лимит Bot API — 50 МБ на документ; при превышении скрипт падает с явным
сообщением, а не молча перестаёт выгружать.

### Учебное восстановление

Непроверенный бэкап — не бэкап: о том, что архив не разворачивается, узнают ровно тогда, когда
он нужен. Раз в квартал стоит прогонять:

```bash
bash /opt/prashna-bot/deploy/restore-test.sh          # последний архив
bash /opt/prashna-bot/deploy/restore-test.sh /путь/к/архиву.gz
```

Скрипт распаковывает копию в `/opt/prashna-bot/restore-test/`, проверяет `integrity_check`,
наличие всех четырёх таблиц и печатает счётчики — сколько пользователей, прашн, когда был
последний вопрос. Рабочая база не затрагивается. Любой сбой — ненулевой код возврата.

Результат прогона 20.09.2026 на боевом архиве (`prashna-2026-09-19-2235.sqlite3.gz`, 24 КБ):

```
==> 2/4 Целостность
integrity_check: ok
==> 3/4 Схема
geocache prashna sqlite_sequence usage users
==> 4/4 Данные
пользователей: 2
прашн: 20
последний вопрос: 2026-09-18T22:58:45.178314+00:00
записей о лимитах: 7
геокэш: 0
```

Пустой `geocache` — не потеря данных: кэш заполняется только при геокодировании города по
названию, а место, полученное из геолокации Telegram, в Nominatim не ходит.

Чтобы убедиться, что на копии поднимается сам бот, нужно остановить основной: два long polling
с одним токеном дают от Telegram `409 Conflict`.

```bash
systemctl stop prashna-bot
cd /opt/prashna-bot && DB_PATH=/opt/prashna-bot/restore-test/prashna.sqlite3 .venv/bin/python run.py
# отправить боту любой вопрос, увидеть карту и ответ, затем Ctrl+C
systemctl start prashna-bot
```

Журналы systemd не разрастаются бесконечно, но ограничение не помешает:

```bash
journalctl --vacuum-size=200M
```

## 5. Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `TELEGRAM_TOKEN` | — | Токен от BotFather (обязательно) |
| `GROQ_API_KEY` | — | Ключ Groq (обязательно) |
| `GROQ_MODEL` | `llama-3.3-70b-versatile` | Модель Groq. Список актуальных моделей — в консоли Groq |
| `GROQ_BASE_URL` | `https://api.groq.com/openai/v1` | Совместимый с OpenAI эндпоинт |
| `GROQ_TIMEOUT` | `90` | Таймаут запроса, секунд |
| `GROQ_MAX_TOKENS` | `1800` | Максимум токенов ответа |
| `DB_PATH` | `/opt/prashna-bot/data/prashna.sqlite3` | Файл SQLite |
| `LOG_LEVEL` | `INFO` | `DEBUG` для отладки |
| `DAILY_LIMIT` | `5` | Прашн на пользователя в сутки |
| `COOLDOWN_SECONDS` | `30` | Пауза между вопросами |
| `ADMIN_IDS` | — | ID админов через запятую (доступ к `/stats`) |
| `SUPPORT_CONTACT` | — | Контакт в `/paysupport`: `@username` или почта. Пусто — команда отвечает правилами возврата без контакта |
| `DEFAULT_CITY` / `DEFAULT_LAT` / `DEFAULT_LON` / `DEFAULT_TZ` | Москва | Место, если пользователь не задал своё |
| `GEOCODER_URL` | Nominatim | Можно заменить на свой инстанс Nominatim |
| `GEOCODER_UA` | — | User-Agent с контактом — требование Nominatim |
| `LLM_PROXY_FALLBACK` | — | Запасной прокси: ретраи бьют в тот же адрес и от падения первого не спасают |
| `LLM_PROXY_TIMEOUT` | `55` | Таймаут через прокси, секунд. Меньше `GROQ_TIMEOUT`, иначе переключаться некогда |
| `LLM_SLOW_NOTICE` | `25` | Через сколько секунд предупредить, что ответ идёт дольше обычного |
| `AYANAMSA` | `LAHIRI` | `LAHIRI`, `RAMAN`, `KRISHNAMURTI`, `YUKTESHWAR`, `TRUE_CITRA` |

## 8. Возможные проблемы

| Симптом | Причина и решение |
|---|---|
| `Не заданы обязательные переменные окружения` | Не заполнен `.env`. `nano /opt/prashna-bot/.env`, затем `systemctl restart prashna-bot` |
| `TelegramUnauthorizedError` | Неверный `TELEGRAM_TOKEN` либо бот удалён в BotFather |
| В логах `Groq недоступен: 401` | Неверный или отозванный `GROQ_API_KEY` |
| `Groq недоступен: 400 model_not_found` | Модель снята с обслуживания — поставьте актуальную в `GROQ_MODEL` |
| «Сервис толкования недоступен» у пользователей | Исчерпан бесплатный лимит Groq (429). Подождите либо снизьте `DAILY_LIMIT` |
| `Не нашёл такой город` | Nominatim ограничивает частоту и требует корректный `GEOCODER_UA`. Попросите пользователя прислать геолокацию |
| Ошибка сборки `pyswisseph` | Не хватает компилятора: `apt install -y build-essential python3-dev` |
| `Conflict: terminated by other getUpdates` | Запущено две копии бота — остановите лишнюю (`systemctl stop prashna-bot`, проверьте локальный запуск) |
| Сервис падает по памяти | Снимите `MemoryMax=512M` в unit-файле либо добавьте swap: `fallocate -l 1G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile` |

## 9. Замечания по астрологии и ответственности

* Прашна корректна только для **искреннего, вызревшего вопроса**. Повторные вопросы на
  одну тему в короткий срок традиционно не рассматриваются — отсюда дневной лимит.
* Карта строится на момент получения сообщения ботом и **на место вопрошающего**,
  поэтому корректно указанный город важен.
* Автоматическое определение бхавы работает по ключевым словам. Если вопрос сформулирован
  необычно, бот возьмёт 1-й дом; при желании список слов расширяется
  в `app/astro/constants.py` → `HOUSE_KEYWORDS`.
* Толкование — предмет для размышления, а не медицинское, юридическое или финансовое
  указание. Эта оговорка выводится пользователю в `/start`.
